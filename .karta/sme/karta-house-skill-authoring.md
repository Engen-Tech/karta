## Do
- State every cross-file term — marker grammar, mode name, phase id, report line format — identically everywhere it appears; quote the canonical wording, never paraphrase it. A binder declares such a string as a `shared_terms` entry, and `check_shared_terms.py` then enforces it — asserting byte-identity across the listed items at deliver and build time — so the identity is a checked invariant, not a wish.
- Give every new invariant an enforcement point (a validator, a gate, a hook); prose alone is a wish.
- Model new scripts on the house pattern: stdlib-only, argparse, a `--self-test` mode with [PASS]/[FAIL] lines.
- Write human-facing prose (README, docs/how-to, release notes) in plain language: lead with what the reader does, short sentences, no unexplained codenames.
- When a self-test cannot exercise real runtime behavior (a browser, a network round trip, a UI timer), say so plainly in the build report: name what was verified by direct call or by static inspection of rendered source, and what was not verified at all, rather than letting a passing self-test imply end-to-end coverage (seen 2026-08-15, watch-derivation-cost delivery).
- State a numeric bound (a byte ceiling, a call count, a timeout) together with the condition it was measured under — input size, fixture shape, machine — never as a bare number; measure it at more than one point on that axis so the bound is reproducible rather than asserted (seen 2026-08-15, watch-derivation-cost delivery).
- When a self-test needs to prove that a rendered value actually derives from a source constant rather than merely matching it once by coincidence, drive the render through a template/function pair (e.g. `_CSS_TEMPLATE` + `_css_from(...)`) and assert at more than one input value, so a literal hand-typed in place of the real derivation fails the test. A self-test that only checks a single current rendering can pass even when the dependent value was pinned by hand instead of computed (seen 2026-08-18, watch-fidelity delivery: seven items collapsed scattered stylesheet literals into named constants, and the bar height, the ring pair and the four radii are the ones `_css_from` actually takes as parameters — so those are the ones re-rendering proves. The constants left hand-pinned in the template are exactly the ones a literal could still be swapped into without the suite noticing, which is the point: a derivation is proven only for the inputs the render is driven at).
- When describing what a source-text guard proves (a binder's `verification_honesty`/`assertions` fields, a self-test comment, a build report), never phrase the claim as "mutation X turns the check red." That is a claim about EDIT HISTORY, while a guard that inspects committed source only ever sees FINAL TEXT — any arrangement of final text that satisfies the guard passes regardless of how it was reached, so a reviewer can always construct a counterexample edit that keeps the guarded text present while the real behavior breaks. State the property the check actually tests instead (e.g. "fails when fragment F is absent from the body span" or "fails when the first statement is not S"), and treat a named mutation only as a demonstration that the straightforward edit trips that property — never as proof the guard detects the general class of edit (seen 2026-08-24, watch-drill-in-remediation delivery: fourteen review rounds across two items — twin-guards and fact-trace-archive — rejected every "mutation X turns the suite red" phrasing in turn before landing on the final-text-property form).
- When a negative control selects its target by position (a fixed index, an offset into a list) rather than by identity (a name, a stable key), re-check that the selection still lands on the intended target whenever the underlying fixture data changes — position can silently retarget onto now-passing data and turn a mutation into a no-op that a check still reports green (seen 2026-08-24, watch-font-adherence delivery: a frozen check's negative controls selected face index 0, which became the new variable-font face when Newsreader was re-cut; the harness's vacuity guard caught the resulting no-op).
- When an agent's phase contract requires it to end with a specific action (e.g. "ends with exactly one `docs: gardner <slug>` commit"), confirm the agent's own tool list actually grants a way to perform that action — a shell tool for a commit, or the equivalent for whatever the contract names. A contract an agent cannot satisfy on its own is silently completed by whoever dispatched it, which is a different actor than the doctrine names (seen 2026-08-24, watch-font-adherence delivery: `karta-doc-gardner` is defined without a shell tool while its phase specifies ending with exactly one `docs: gardner <slug>` commit; it edited correctly and could not commit the result, and the orchestrator had to).

## Don't
- Don't edit a mirror or `references/` copy by hand — edit the canonical file (`skills/_shared/`, `skills/*/SKILL.md`, `agents/*.md`) and run the sync writers.
- Don't move or rename a phase, step, or file and leave old pointers to it standing in other doctrine files.
- Don't add a new shared file without confirming `check_shared_copies.py` covers its copies.

## Patterns
- Canonical → generated: `skills/_shared/` and `agents/*.md` are sources; `.agents/`, `plugins/`, `.codex/`, and `references/` copies are outputs of the sync scripts.
- Small validators over prose promises: the `validate_binder.py` / `validate_packs.py` shape — parse strictly, fail closed, self-test.

## Review checklist
- [ ] house.1 — A diff editing a canonical `skills/_shared/`, `skills/*/SKILL.md`, or `agents/*.md` file carries its regenerated mirror copies in the same change.
- [ ] house.2 — Every new script under `scripts/` or `skills/*/scripts/` ships a runnable `--self-test` mode.
- [ ] house.3 — No doctrine pointer (phase id, step name, path) still refers to a location this same diff moved or renamed.
- [ ] house.4 — A new check that asserts an invariant (a self-test assertion, a validator rule, a regression guard) ships in the same diff with a companion negative case — a deliberately violating fixture, a mutation, or a known-bad input — proving the check can actually fail. A check never exercised against a failing case is not known to work (seen 2026-08-15, watch-derivation-cost delivery: git-call-count-invariant's per-binder-derivation negative control, lean-box-benchmark's five mutation tests, cache-derived-state's suppressed-key backstop test). A negative case that fails, but for a different reason than the one its docstring or comment names, does not satisfy this rule — the stated failure reason must match why the check actually fails, or a pass proves nothing about which mistake the check catches (seen 2026-08-24, watch-font-adherence delivery: a deliberately-wrong control's docstring claimed a transform-version rule that contradicted the real reader in the same file; the control still failed the check, but for two reasons at once, so a pass would not have identified which mistake the reader avoided).
